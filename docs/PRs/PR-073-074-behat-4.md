# PR #73 and #74 - Behat 4 (Dependabot)

- **Author:** Dependabot
- **Branches:** `dependabot/composer/behat/behat-tw-3.29or-tw-4.0` (#73) and
  `dependabot/composer/tests/functional/behat/behat-tw-4.0` (#74) → `ideaconnect:main`
- **PRs:** https://github.com/ideaconnect/symfony-nats-messenger/pull/73,
  https://github.com/ideaconnect/symfony-nats-messenger/pull/74
- **Status:** Adapted in #79, which moves every development dependency to its newest release; neither was
  merged directly.

## What the PRs Proposed

1. **#73** raised the root `require-dev` constraint on `behat/behat` from `^3.29` to `^3.29 || ^4.0`. Its CI
   passed: no root script runs Behat, and the functional suite runs the copy installed in `tests/functional`,
   which stayed on Behat 3.
2. **#74** raised the functional test app's constraint from `^3.29` to `^4.0`. Its CI failed on every job.

## Why #74 Failed

Behat 4 reads neither YAML configuration nor doc-comment annotations. It found no configuration it could load
in `tests/functional/behat.yml`, fell back to its default context and stopped:

```text
`FeatureContext` context class not found and can not be used.
```

## How It Was Adapted (#79)

- `tests/functional/behat.yml` became `behat.php`, written by `behat --convert-config`.
- The context's 94 step definitions and its `AfterScenario` hook became attributes (`#[Given]`, `#[When]`,
  `#[Then]`, `#[AfterScenario]`), converted with Rector's Behat attribute set. The patterns are unchanged.
- `behat.php` turns on strict result interpretation. Behat 4 does not register a step left as a doc-comment
  annotation, and without strict interpretation a scenario using it is reported as undefined while the run
  exits 0, so a lost definition would have passed CI. `FunctionalSuiteConfigTest` loads `behat.php` with the
  root's Behat config classes and checks the setting, which is also why the root keeps `behat/behat`.
- `run_tests.sh` and the functional README name `behat.php`, list definitions with `--definitions l` (Behat 4
  requires a value), and say that a dry run, which skips every step, exits 1 under strict interpretation.
- `--tags '~@delayed'`, which the oldest-NATS job uses, still works on Behat 4. The new Cucumber form
  `not @delayed` selects nothing without extra configuration, so the job is unchanged.
- Both manifests require `^4.0`. The rest of #79 (PHPUnit 11 to 13, Infection up to 0.35, PHPStan 2.3,
  BypassFinals 1.11, the functional app's Symfony floors) is described in the changelog.

## Review of #79

#79 was opened before #78 (the bundle) was merged, so its green CI never ran against it. A review on
2026-10-16 found it conflicting with `main` in `tests/functional/tests/Behat/NatsSetupContext.php`, where
neither side worked alone: this branch's max-age and TLS steps still defaulted to the `igbinary_serializer` id,
which #78 removed from the test app, and `main`'s side kept the doc-comment annotations Behat 4 ignores. The
merge of `main` keeps the attributes and #78's `IgbinarySerializer::class` value. Further commits, one per
finding:

| Finding | Resolution |
|---------|------------|
| Undefined steps did not fail the functional suite | Strict result interpretation in `behat.php`, guarded by `FunctionalSuiteConfigTest` |
| `behat --definitions` without a value fails on Behat 4 | `--definitions l` in `run_tests.sh` and the functional README |
| The PHPUnit 13 clean-up was not enforced | `failOnPhpunitDeprecation` in `phpunit.xml.dist`; CI's PHP 8.5 job passes `--fail-on-phpunit-notice` (PHPUnit 11 rejects that attribute in the XML file); guarded by `UnitSuiteConfigTest` |
| A stub hid a missing check in the serialization-failure send test | The JetStream double is a mock again, expecting `publish()` never to be called |
| CLAUDE.md said PHPUnit 11 and 13 only | It names 12 too, which PHP 8.3 installs |
| The new conventions were in CLAUDE.md only | AGENTS.md carries them as well |
| `resolveDependencies="true"` is PHPUnit's default | Dropped |
| No record of #73 and #74 | This file |

Left as they are: the root keeps `behat/behat` (the unit suite now loads `behat.php` with it), and the
functional app keeps the newest Symfony 7.4 and 8.1 patch releases as floors.
